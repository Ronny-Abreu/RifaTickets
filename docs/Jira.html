Permitir a usuarios públicos ver rifas, reservar boletos, subir comprobantes de pago y ver actualizaciones del estado de la compra. También permitir a los administradores validar los comprobantes subidos.

h3. Contexto

Esta épica incluye varias historias de usuario para la navegación pública de rifas y el flujo de compra de boletos. También incluye el paso de revisión por parte del administrador para los comprobantes de pago. Algunas acciones deben actualizarse en tiempo real usando listeners de Firestore.

h3. Alcance

Incluido en esta épica:

* Ver rifas activas con tarjetas que muestran título, foto y tiempo restante.
* Ver detalles de los boletos y disponibilidad en tiempo real.
* Seleccionar un boleto disponible y cambiarlo a "Pendiente de pago".
* Subir una imagen de la transferencia de pago y mostrar "En validación" después de la subida.

* Los boletos disponibles pueden reservarse y quedan bloqueados visualmente para otros usuarios.
* Los usuarios pueden subir una imagen como comprobante de pago.
* Después de la subida, el sistema muestra "En validación".
* Los administradores pueden ver los comprobantes pendientes y aprobar o rechazarlos.
* Cuando un comprobante es aprobado, el estado del boleto cambia a "Comprado" en la UI pública inmediatamente.

h3. Riesgos y dependencias

* Se requieren listeners de Firestore para actualizaciones de UI en tiempo real.
* La reserva de boletos debe prevenir que otros usuarios seleccionen el mismo boleto.
* La validación de comprobantes depende del dashboard de admin y sus acciones de aprobar/rechazar.

* Bloquear visualmente el boleto para otros usuarios.
* Otros usuarios que estén viendo el mismo evento deberían ver el boleto como bloqueado o no disponible, con un indicador visual claro y, si es apropiado, una cuenta regresiva que muestre cuánto tiempo se mantendrá la reserva.
